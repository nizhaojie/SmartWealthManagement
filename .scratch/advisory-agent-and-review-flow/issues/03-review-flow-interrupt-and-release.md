# 03 — 审核流：中断、放行驳回与并发加锁

**What to build:** 生成流程在产出 AI 原稿后停下来等人，理财顾问放行后才产生顾问定稿——这是唯一允许送达客户的版本。放行时系统重新校验推荐产品仍在候选池内，因为顾问的手工编辑可能意外引入越级产品。客户经理看得到但放不了行。

这里最容易做成橡皮图章：加一个「已审核」布尔字段、点一下置真。那样系统上合规、举证时站不住——原稿与定稿并存、差异可计算，才是这条红线真正的实现。

**Blocked by:** 02 — AI 原稿落库与内容分类

**Status:** ready-for-agent

- [ ] 用运行时的中断机制实现暂停与恢复，状态持久化由检查点承担，不自己实现（ADR-0007）
- [ ] 放行后产生顾问定稿，原稿与定稿并存且差异可计算
- [ ] **护栏测试：未经审核的投顾内容无法通过任何客户侧接口读取**
- [ ] 客户侧接口读到的是定稿，不是原稿
- [ ] **只有理财顾问角色能放行**；客户经理调用放行接口被拒绝
- [ ] **放行时重新校验推荐产品仍在候选池内**，顾问编辑引入越级产品则放行被拒绝
- [ ] 驳回必须填写理由，理由为空被拒绝
- [ ] 同一份内容在审核期间加锁，并发编辑时第二个请求被拒绝或排队
- [ ] 每次审核记录审核人、时间与操作
