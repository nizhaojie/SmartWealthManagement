# 06 — 输入区与空态的四处返工

**What to build:** 数据分析页的四处呈现返工：底部输入区换成客服侧的对话形态（左侧图标、单行、回车发送、没有换行）；「历史查询」从顶栏搬到页头「清空对话」的右侧；空态引导去掉限宽、铺满面板宽度；「试试这些」示例问题点击后**只填进输入框**，不再自动发送。

**Blocked by:** 03（对话壳与输入区）、05（历史查询进抽屉）——这两份交付的东西本次有三处被推翻（下面第 11 行的表）；文件末尾另有一次同日的追加返工。

**Status:** ready-for-agent

**本 ticket 推翻的既有决定（不静默偏离，逐条记下）：**

| 原决定 | 出处 | 本次改为 | 为什么 |
|---|---|---|---|
| 多行自适应输入框 + Ctrl+Enter 发送，Enter 换行 | spec Q14、ticket 03 | 单行输入，**回车发送、没有换行** | 与客服侧的对话输入取同一形态（同一系统里两处对话输入不该有两套回车约定）。中文输入法组字时的回车由输入法吃掉，不会再误发半句——这与「Enter 留给换行」原本要防的是同一件事，做法换了、保证没丢 |
| 「历史查询」挂 `AppShell` 的 `topbar-right` | spec Q9、ticket 05 | 页头操作区，「清空对话」的右侧 | 两个动作同属「这一页的对话控制」，分居顶栏与页头时不成组。第三栏仍然不渲染（`inspector` 插槽依旧不注入），两栏形态不变 |
| 空态示例问题**点击直接发问** | spec 的「对话壳与输入」、ticket 03 | 点击**只填入输入框**，发不发、要不要先改几个字由员工决定 | 与抽屉里「再问一次」取了同一条语义：示例只是把一句话送到手边，不是替人提问 |

- [ ] 占位文案里的快捷键说明跟着改（`（Ctrl + Enter 发送）` → `（回车发送）`），否则它会指向一个已失效的操作

**与客服侧**有意**留的一处不同（别顺手抹平）**：输入框自己的描边留着——客服侧在 `.composer` 上把 `el-input__wrapper` 的描边去掉了，这一页不去。两条输入带的底色不同（客服侧 `--wm-bg-page`、这一页 `--wm-bg-subtle`），图标底座与输入框之间留一道描边，输入区的边界才看得出来。两侧 composer 的「同形」到图标 + 单行 + 回车提交为止；Q8 已经认下「不进 shared、各写一份」的代价，这里只是把那笔代价写明，供后来者按需取舍。

**实现落点：** `apps/internal/src/analytics/MessageComposer.vue`、`EmptyConversation.vue`、`DataAnalysisWorkspace.vue` 与同目录三个 spec。**不进 `packages/shared`**（Q8 的同一条理由）。

**后续推翻（2026-09-24，用户提出）**：上面那条「与客服侧**有意**留的一处不同」不再保留，方向反过来——**客服侧向这一页看齐**；另修一处静默失效的布局。这一节同样越过了 `spec.md` 的 Out of Scope「客户侧任何改动：本次不动 `apps/customer`」——越过的是**样式**，`apps/customer` 的对话逻辑、引用呈现面与 SSE 接线一行不动。

| 原决定 | 本次改为 | 为什么 |
|---|---|---|
| 客服侧 composer 去掉 `el-input__wrapper` 描边，输入带底色 `--wm-bg-page`、分隔线 `--wm-border` | 客服侧恢复输入框自身描边，底色改 `--wm-bg-subtle`、分隔线改 `--wm-border-hairline`，与本页 `MessageComposer` 同形 | 「一处有框、一处无框」只记在 ticket 里，界面上没有任何线索说明它是有意的；同一个系统里两处对话输入，形态差别要让位于一眼是同一样东西。改的是**整条输入带**（描边、底色、分隔线），只改输入框自身会剩下一圈颜色不合的底，看着仍不是同一样东西 |
| 数据分析页 `.analytics` 写 `height: 100%`「占满可用高度」 | 壳的内容区 `.shell__content` 加 `min-height: 100%`，页根改 `flex: 1` | 这一条**从来没有生效过**：`.shell__content` 是 `height: auto`（只跟内容一样高），页根的百分比高度到它这里静默解析成 auto——面板高度只跟内容走，消息少时比客服侧的窗口矮一截，消息多时是整页在滚而不是线程自己滚。客服侧 `ChatPage` 是 `.app-shell__content` 的直接子级、那一层高度确定，才用得上百分比 |

**落点说明：** 只加 `min-height`（不是 `height`）是这次敢动壳层包裹的理由——`.shell__content` 由全部内部模块页共用，加下限只保证「页根若要占满高度，有高度可依」，比可用高度更高的页面照旧把它撑高、外层 `.app-shell__content` 照旧滚；两个应用的页根里没有第二处依赖它的 `height: 100%`。

**已知残差（不抹平，留在这里备查）：** 两侧输入框还剩一处不同，是**行为**不是样式——客服侧发送中给 `el-input` 挂了 `:disabled`（EP 会把输入框灰化），数据分析侧不在提交时禁用、只在 `submit()` 里拦下这一下（输入框保持可用，字原样留着）。本次只对齐样式，不动这一处。

**验收（这次）：** 数据分析页在空态、一轮、多轮三种情形下面板都铺满可用高度（不再随内容长短伸缩），消息多时是线程自己出滚动条、页头与输入框始终可见；客服侧输入框恢复自身描边，输入带的底色与分隔线与数据分析页一致，且历史记录、引用角标、断流兜底话术照旧。

**实现落点（这次）：** `apps/internal/src/shell/WorkbenchShell.vue`、`apps/internal/src/analytics/DataAnalysisWorkspace.vue`、`apps/customer/src/chat/ChatPage.vue`。不新增测试：两侧都只改样式，沿袭本 slice「不测排版」的口径（`pnpm typecheck` 与 `pnpm test` 全绿）。

**验收：** 输入框左侧有图标、单行、按回车直接发出且输入框里不可能出现换行；「历史查询」在「清空对话」右边，点开是抽屉；空态那句引导铺满面板宽度；点一条「试试这些」只把问题填进输入框，页面上不出现新一轮问答。
