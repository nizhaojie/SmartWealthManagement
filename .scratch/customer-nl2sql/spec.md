# 客户端数据查询（智能客服接入 NL2SQL）

Status: ready-for-agent

前置：`data-analysis-agent`（已实现，语义视图 + NL2SQL + 安全校验 + 受限账号）、`foundation-and-customer-service-slice`（已实现，客服 Agent 与 SSE）、`operation-advice-and-customer-trading` / `customer-deposit`（已实现，客户交易流水的数据面完整）。

**本 slice 新增 ADR-0025**（客户数据查询复用分析链路，以客户域视图隔离，且只筛不排序），并改 `CONTEXT.md` 两处词条（语义视图、智能客服 Agent，已落）。

## Problem Statement

**客户在今天只能「翻页面」看自己的数据。** 持仓、流水、余额都有 REST 页面（`backend/app/api/customer_assets.py`、`customer_transactions.py`、`funding_account.py`），但对话里问「我持有哪些产品」「这个月充了多少」时，客服只能从知识库里捞——它唯一的工具是 `knowledge_search`（`backend/app/agent/config.py:19-23`），工具集里没有任何数据能力。

**而 NL2SQL 这条链路员工侧已经完整**：语义视图目录、只读校验、受限账号 `wealth_analytics` + 会话变量注入身份、fail closed（`backend/app/analytics/`）。缺的不是能力，是**客户身份落不进现有视图**——`va_*` 的行级条件是员工侧口径（`WHERE 角色 IN ('理财顾问','风控专员') OR manager_id = 员工id`，迁移 `0008`），脱敏口径也按员工固化，客户套不进去。

**一条边界必须先钉住**：`CONTEXT.md` 写死「智能客服工具集内不存在推荐类能力」。客户问「有什么适合我的产品」时，NL2SQL 允许做到哪一步，是这个 slice 最大的决定（Q1）。

## Solution

**客服图增加一条「数据查询」分支**：`classify` 增加一类，确定性路由到复用的 analytics 链路（选视图 → 生成 → 校验 → 执行 → 解读），不引入 tool-calling，不另建 NL2SQL 管线。

**新建客户域语义视图，不动员工侧五个**：行级条件内建「客户 = 凭证客户」，未设置返回零行（fail closed，与 0008 同手法）；受限账号同账号授权新视图。产品要素查询复用无行级过滤的 `va_product_element`（产品是已披露信息）。

**结果以文本解读送达**：SSE 帧协议与前端零改动，数字直接写进解读文本。

**失败与越界是回答的一部分**：失败/超时明说查不了并写降级留痕，**绝不回退到知识检索**；白名单外明确告知可查什么；零行如实说没有数据——零行与失败必须区分，前者是事实，后者是降级。

## Implementation Decisions

遵循 `docs/adr/`。本 slice 直接受 ADR-0025（本次新增）、ADR-0005（筛选不是推荐）、ADR-0009（护栏测试）、ADR-0010（NL2SQL 只作用于语义视图）约束。**员工侧五视图、`validate_query`、受限账号机制、SSE 协议全部不动。**

### 客户域语义视图（issue 01）

- 迁移脚本新建视图（命名实现时定，建议 `va_my_*`）：**持仓明细**、**交易流水**、**资金账户**三张，列面以客户既有 REST 接口的数据面为准（`customer_assets` / `transactions` / `funding_account`）；**本人数据不脱敏**——「自己看自己」没有脱敏对象。
- 追加第四张 `va_my_risk_assessment`：只含风险承受等级结论列。它是 Q1(B) 的机制前提——Cn 筛 R1–Rn 需要等级结论进 SQL 可见范围；它在 `CONTEXT.md` 客户可见视图边界内（风险测评等级结论），不违反 Q2「三张」的白名单意图。
- 行级条件沿用 0008 手法：会话变量读身份，**未设置返回零行（fail closed）**；实现时定「新会话函数」或「直读变量」，与员工侧函数命名区分。
- 受限账号同账号授权：`wealth_analytics` 增授四张新视图 + `va_product_element`（产品要素本无行级过滤，是已披露信息，产品筛选直接用它）。
- 视图各带口径说明与关键词，供视图匹配注入。

### 客服图接入（issue 02）

- `classify` 增加数据查询一类，确定性路由到复用的 analytics 链路（选视图 → 生成 → 校验 → 执行 → 解读）。候选视图目录限客户域白名单，**员工侧四视图（含预警统计）不在客户候选集**。
- 身份注入改客户口径：执行前 `SET` 客户凭证标识（对应 `require_customer` 解出的身份）；记忆沿用客服既有短期记忆（JWT `sid`、客户命名空间），上一轮提问并进视图匹配语境与 analytics 现状一致。
- 解读输出面向客户的事实性文本，数字直接写进文本（Q5A），不带投资评价；SSE、`ChatRequest`、前端零改动。
- 三套响应话术（Q6）：失败/超时 → 「暂时查不了，稍后再试或去资产页查看」+ 写降级留痕（复用 `biz_degradation_trace`）；白名单外 → 告知不在可查范围并列出可查什么；零行 → 如实说。**任何路径都不回退到知识检索。**
- 高风险意图识别路径不变：数据查询的问题照常过它。

### 护栏与收口（issue 03）

- 护栏测试 3 扩展客户段：只读、越权视图拒绝（预警统计等员工视图取不到）、行级范围锁死为凭证客户、**注入/伪造会话变量也改变不了范围**、未设置身份返回零行。
- 客服既有断言（引用契约、高风险意图、SSE 帧序列）全部保持通过。

## Testing Decisions

沿用既有后端 HTTP 测试模式，不新增测试 seam。

- 客户登录后问「我持有哪些产品」，得到含自己持仓数字的文本回答（事实性内容，无引用角标要求——引用是知识检索的契约，数据回答的依据是查询本身）。
- 问「有什么适合我的风险等级的产品」：返回只筛不排序、按产品代码排序的产品清单，且不含推荐话术。
- 问「我的画像标签是什么」：得到白名单外语术，**不是**知识库兜底答案。
- 迁移后不设置身份直接查新视图：零行。
- 既有护栏测试 3 员工段、客服链路断言全数保持通过。

`pnpm typecheck` 与 `pnpm test` 收尾必须全绿。

## Out of Scope

- **表格帧 / SSE 协议改动**（Q5A）：前端零改动是本 slice 的边界，表格渲染另开 spec。
- **已签署文件、风险测评结论之外的第二批视图**（Q2）：测评结论那张是 Q1(B) 的机制前提才进来的，其余数据第二批再说。
- **画像、服务记录、风控预警**：在客户可见视图边界外，永不进白名单。
- **排序与阐述**：产品查询只筛不排序；排序、评分、推荐理由是投顾助手的输入范围（ADR-0005）。
- **多轮下钻、图表化**：沿袭 `data-analysis-agent` 的既有排除。

## Further Notes

- **`CONTEXT.md` 的改动（已落）**：**语义视图**扩展出客户域口径（两套互相独立、客户域锁凭证客户、未设置返回零行）；**智能客服 Agent** 补一句数据查询能力及「只筛不排序、仍不构成推荐」的边界。不新增词条。
- **ADR-0025（已落）**：核心记录 Q1(B) 的取舍——为什么客服可以拿风险承受等级过滤产品却不违反「工具集内不存在推荐类能力」，以及「复用分析链路、客户域隔离、失败不回退知识检索」三个被拒绝的备选。
- **`docs/roadmap.md` 的改动**：横切 slice 段落补一条本 slice 的说明 + 收尾清单补一行。
- **零行与失败必须区分**是本 slice 的品味线：前者是事实（如实说没有），后者是降级（留痕、话术、绝不冒充）。
- **评分表里「安全事故（SQL 注入、无权限校验）-10」同样对着这条新链**：客户侧把 NL2SQL 暴露给了外部身份域，安全性仍然押在「模型看不到基础表 + 行级条件内建在视图定义里」上，不押在提示词上。任何想给客户视图「开个口子直查基础表」的提议都应被这条 ADR 挡回去。
