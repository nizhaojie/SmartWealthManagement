# 数据分析 Agent

Status: ready-for-agent

前置：`internal-workbench-shell`（内部工作台外壳）

## Problem Statement

内部员工想知道一个业务数字——上季度各产品类型的平均收益率、资产超过一百万的客户有多少、某位客户最近一个月的交易——现在要提工单给 IT，由数据工程师写 SQL 导出。一个五分钟就能回答的问题，走完流程要一到两天。

直接把数据库开放给员工查询解决不了问题：多数员工不会写 SQL，而且一旦开放，谁能查到哪些客户的哪些字段就完全失控了。

让模型直接对着基础表生成 SQL 也不行——那样脱敏和权限就只能靠在提示词里嘱咐模型「别查身份证号」，这是一条概率性的防线，一次不听话就是一起数据泄露。

## Solution

员工用日常语言提问，系统生成查询、执行、并把结果集用自然语言解读一遍。

安全性由结构保证而非由提示词保证（ADR-0010）：模型只看得到**语义视图**——预先定义的、已脱敏、内置行级权限过滤的只读视图。敏感字段不在视图里，因此无论模型生成什么查询都取不到；「查别人的数据」在 SQL 层就不成立。语义视图没覆盖的问题，Agent 明确说答不上来。

生成的查询在执行前还要过一道校验：只允许只读查询，结果行数有上限。这是第二道防线，不是唯一防线。

## User Stories

### 内部员工

1. As an 内部员工, I want to 用日常语言提出数据问题, so that 我不必会写 SQL
2. As an 内部员工, I want to 看到系统生成的查询语句, so that 我能判断它有没有理解我的问题
3. As an 内部员工, I want to 结果以表格呈现, so that 我能逐行阅读
4. As an 内部员工, I want to 结果附一段自然语言解读, so that 我不必自己从数字里总结结论
5. As an 内部员工, I want to 把结果导出, so that 我能拿去做进一步分析
6. As an 内部员工, I want to 系统答不上来时明确说明原因（问题超出可查范围 / 无法生成查询）, so that 我知道是换个问法还是这事根本查不了
7. As an 内部员工, I want to 看到本次查询涉及哪些数据范围, so that 我理解这个数字的口径
8. As an 内部员工, I want to 连续追问时系统记得上一个问题, so that 我能说「那上个季度呢」而不必重述
9. As an 内部员工, I want to 结果超过行数上限时被明确告知, so that 我不会把一份被截断的数据当成全量
10. As an 内部员工, I want to 查看我自己的历史查询, so that 我能重用之前问过的问题
11. As an 内部员工, I want to 看到几个示例问题, so that 我知道这个工具能回答什么样的问题
12. As an 内部员工, I want to 查询耗时较长时看到进度反馈, so that 我不会以为它卡死了

### 合规与安全

13. As a 合规负责人, I want to 生成的查询只能作用于语义视图, so that 敏感字段在结构上就取不到
14. As a 合规负责人, I want to 行级权限内建在视图里, so that 越权读取在 SQL 层不成立
15. As a 合规负责人, I want to 任何写操作一律被拒绝, so that 这个入口不可能改动数据
16. As a 合规负责人, I want to 试图用提示词注入绕过限制时仍然拿不到视图外的数据, so that 防线不依赖模型是否听话
17. As a 合规负责人, I want to 每次查询留下永久记录（提问人、问题、生成的查询、返回行数）, so that 事后可追溯谁查了什么
18. As a 合规负责人, I want to 面向客户的报告类输出附带免责声明, so that 内部数据解读不被当作投资建议对外流传

### 开发者

19. As a 开发者, I want to 语义视图的定义集中在一处, so that 新增一类分析需求是加一个视图而不是改散落各处的查询
20. As a 开发者, I want to 只把与问题相关的视图定义注入模型, so that 提示词不会随视图增多而无限膨胀
21. As a 开发者, I want to 少量「问题 → 查询」示例可配置, so that 我能通过补示例提升生成准确率而不改代码

## Implementation Decisions

遵循 `docs/adr/`，核心是 ADR-0010（语义视图）与 ADR-0007（LangGraph 运行时）。

### 语义视图

预先定义一组只读视图，覆盖客户概况、持仓分布、交易统计、产品要素、预警统计等分析场景。视图中：

- **敏感字段不出现**——身份证号、手机号、银行卡号、密码散列一律不进视图；真实姓名按脱敏规则出现
- **行级权限内建**——视图定义中带上按当前身份过滤的条件，越权读取在 SQL 层不成立
- **口径固定**——例如「资产规模」在视图里是一个明确定义的字段，不由模型临时拼接聚合逻辑

视图集合会随需求增长，这是这个决定的常态开销（ADR-0010）。视图没覆盖的问题，Agent 明确回答「超出可查范围」，**不退回去查基础表**。

### 查询生成

只把与问题相关的视图定义注入模型（按问题中的关键词筛选），而不是注入全部——否则提示词会随视图增多而膨胀。

提供少量「问题 → 查询」示例提升准确率，示例可配置。

### 执行前校验

第二道防线，不是唯一防线：

- 只允许只读查询，写类操作与结构变更一律拒绝
- 结果行数有上限，超出时截断并**明确告知已截断**
- 查询有超时上限

校验失败返回明确的业务错误码，不返回 500。

### 结果解读

结果集与原始问题一起送入模型生成自然语言描述。解读要说明数据口径——同一个「收益率」在不同口径下是不同的数字，只给结论不给口径会误导。

若生成的是**面向客户的报告类内容**（投资研报、财富报告、行业分析），输出必须附免责声明。纯内部数据查询不需要。这条边界按 `CONTEXT.md` 的投顾内容与事实性内容之分判定。

### Agent 配置

作为 LangGraph 运行时上的一份配置（ADR-0007）：提示词、工具集（查询生成与执行）、短期记忆策略、内容分类默认值为事实性内容。

多轮追问依赖短期记忆——「那上个季度呢」需要上一轮的问题作为上下文。

### 界面

内部工作台的一个模块，落在既有外壳里。界面包含：提问输入、生成的查询语句（可折叠）、结果表格、自然语言解读、导出入口、历史查询列表、示例问题。

生成的查询语句默认折叠但可展开——员工需要能判断系统有没有理解自己的问题，但多数时候不想看 SQL。

## Testing Decisions

沿用两个 seam。

### Seam 1 — 后端 HTTP 层

核心是护栏测试 3：

- **写类操作与结构变更一律被拒绝**（护栏测试 3）——覆盖删除、更新、插入、结构变更、清空等各类
- 试图通过提问诱导模型访问视图外的对象时，执行仍然失败或返回空，取不到基础表数据
- 提示词注入式的提问（例如要求忽略先前指令）不改变可访问的数据范围
- 员工 A 的凭证通过视图只能拿到其权限内的行
- 返回结果中不含身份证号、手机号、银行卡号
- 结果超过行数上限时被截断且响应中带有截断标记
- 无法生成合法查询时返回对应业务错误码
- 多轮追问时上一轮问题进入上下文
- 每次查询在留痕中留下记录

模型用 `fake` provider，因此生成的查询是确定性的。针对「模型试图越权」的用例，`fake` provider 需要能被配置为返回指定的恶意查询——这样测的是**校验层与视图层是否拦得住**，而不是模型是否乖。

### Seam 2 — Vue 组件挂载

- 结果表格渲染返回的行
- 自然语言解读与表格同时呈现，不是只有表格
- 生成的查询语句默认折叠、可展开
- 截断提示在结果被截断时渲染
- 答不上来时渲染原因说明而不是空表格

## Out of Scope

- 图表化展示查询结果（本 slice 只有表格；可视化在各自的业务 slice 中）
- 定时报表与订阅
- 跨库查询与外部数据源
- 查询结果的缓存复用
- 自然语言生成图表类型的推断
- 语义视图的可视化管理界面（视图由迁移脚本定义）

## Further Notes

这份 spec 的安全性全部押在「模型看不到基础表」这一点上。因此评审时最该检查的不是提示词写得好不好，而是**视图定义里有没有漏进敏感字段**，以及**执行时用的数据库账号是否只对视图有权限**。如果执行账号仍然能访问基础表，那么语义视图就只是一层建议，ADR-0010 想要的结构性保证并不成立。

评分表里「安全事故（SQL 注入、无权限校验）-10」正对着这份 spec。相比在提示词里嘱咐模型，视图 + 受限账号是唯一能在答辩时讲清楚的防线。
