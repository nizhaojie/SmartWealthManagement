# 01 — 工程骨架与健康检查贯通

**What to build:** 开发者克隆仓库后，一条命令起全部依赖容器，一条命令起后端与客户端，在浏览器里看到客户端页面显示后端的健康状态。这条链路很窄但贯穿全层——它验证的是后续每个 ticket 都要落在上面的那几样东西：统一响应格式、链路追踪、分级日志、shared 层的 HTTP 客户端、以及 monorepo 的构建是否真的能跑。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] pnpm workspace 建立，客户端应用、内部工作台应用、共享包三个包各自可独立构建
- [ ] 六个容器（MySQL、Redis、etcd、MinIO、Milvus、Neo4j）由一份编排文件启动，端口全部避开默认值，各自有健康检查
- [ ] 后端读取环境配置，缺少 LLM key 时以 fake provider 正常启动
- [ ] 健康检查接口返回各依赖的连通状态，且外层结构为统一响应格式（业务码、描述、数据体、追踪标识）
- [ ] 任意接口的响应都带追踪标识，且该标识出现在本次请求产生的所有日志行中
- [ ] 全局异常处理覆盖业务异常、系统异常、参数校验异常，任何情形都不返回未经包装的堆栈
- [ ] 日志按级别分文件
- [ ] 共享包提供 HTTP 客户端与响应拆包，两个前端应用都经由它发起请求
- [ ] 客户端应用能启动并渲染一个页面，页面上显示从健康检查接口取回的状态
- [ ] Swagger 文档可访问
