# 前端样式重构（浅色骨架 + 设计令牌）

Status: superseded-by `.scratch/frontend-rebuild/spec.md`

> **本 spec 已被取代（2026-09-18）。** `frontend-rebuild` 决定从 0 重写两个前端并按 `02-企业浅色.html` 建立视觉语言，因此本文件中的三条结论不再适用：① 「只换皮、不动信息架构」的纪律；② 设计令牌层的具体值（主色 `#1F6FEB`、圆角 4/8/12、侧栏 220px、单形态外壳）；③ 「复合组件恰好三个，不再多」。
> 本文件保留作为历史记录：它记录的问题陈述、EC 变量主题化路线、以及「shared 边界靠构建期检查」的判断仍然成立，`frontend-rebuild` 沿用了后者。

前置：无——本 slice 横切既有前端（customer 与 internal 的全部页面），不依赖任何未完成的后端能力。

## Problem Statement

两端界面目前处于「能跑但没设计」的状态：

- `apps/customer` 没有应用外壳，顶部一排裸 `el-button` 充当导航，靠组件内 `ref` 切换视图——刷新丢状态、URL 不可分享、浏览器后退键失效。
- `apps/internal` 有深色侧边栏外壳（`#001529`），但是 Element Plus 默认主题直出，与客户端毫无视觉血缘。
- 18+ 个 SFC 的 scoped style 里散落着硬编码色值与间距；`packages/shared` 里已有受对比度测试保护的**图表**令牌，但全局设计令牌层不存在——改一处风格要翻几十个文件。

参考图（`imgs/dashboard.jpg` / `dashboard2.jpg` / `dashboard3.jpg`）提供了一套中后台浅色仪表盘样式作为目标方向。

## Solution

以参考图为**视觉语言与布局骨架**的参照（风格致敬，数值自主，非像素复刻）：

- 两端统一引入浅色骨架：浅色侧边栏 + 顶栏 + 卡片化内容区。
- 导航项维持两端**真实模块**——参考图的导航（仪表盘/产品管理/理财顾问等）与本系统模块无一对应，只借其形，不借其名。
- internal 增加一个**静态模块导航落地页**（纯入口卡片，零数据聚合）；真正的 KPI 仪表盘是 feature，不在本 slice。
- 全部视觉数值收敛进 `packages/shared` 的设计令牌层（ADR-0003 明确允许主题令牌进 shared），Element Plus 经 CSS 变量主题化，不改组件库、不动后端。

## 访谈结论清单（grill-with-docs，2026-09-17）

本 spec 的全部决定来自一次三轮 grilling 访谈，关键分支与排除项：

- 范围：**双应用**，令牌共享；先令牌与壳，后逐页。
- 参考图角色：视觉 + 布局骨架参照；信息架构不跟（其导航与本系统模块不符）。
- 保真度：风格致敬；色值以本仓库受测试保护的令牌为准，不取参考图的具体色。
- 技术路线：EP CSS 变量主题化 + 共享令牌 + 轻量复合封装（恰好三个，见下）；不自建平行样式体系。
- 涨跌色：**红涨绿跌**（中国金融惯例）。参考图的绿涨为西式模板习惯，不采用。只影响趋势/盈亏指示，不动语义状态色。
- 明确排除（Q5 确认的非目标）：暗色模式、移动端/响应式、参考图上有而系统没有的功能（上传持仓截图、添加理财产品、理财顾问列表、真 KPI 仪表盘）、一切后端改动。

## Implementation Decisions

遵循 `docs/adr/`。本 slice 直接受 ADR-0001（Vue3 + Element Plus）、ADR-0003（shared 边界）约束。

### 设计令牌层（packages/shared 新增 theme 模块）

- **CSS 自定义属性是唯一事实源**（`:root` 定义），TS 侧只做只读镜像供 ECharts 等 JS 取色场景使用；不做「TS 为源构建期生成 CSS」。
- EP 主题化通过把 `--el-color-primary` 等变量映射到令牌实现，`tokens.css` 在 EP 样式之后加载。
- 令牌清单（值均经 WCAG 实测，对白底对比度标注于括号）：
  - 主色 `primary #1F6FEB`（4.63，保留既有受测值，不动）
  - 涨跌：`up #C81E1E`（5.74）/ `down #1E7A46`（5.35）
  - 语义：`success #1E7A46` / `warning #B45309`（5.02）/ `danger #C81E1E`——与跌/涨同值但**独立令牌名**，语义分开、未来可分叉
  - 中性：页面底 `#F5F7FA`、卡片面 `#FFFFFF`、边框 `#E5E7EB`、细线 `#EEF0F3`
  - 文字：主 `#1F2937`（14.68）/ 次 `#374151`（10.31，复用既有图表标签色）/ 弱 `#6B7280`（4.83，同上）/ 占位 `#9CA3AF`（2.54，**仅占位与装饰，禁用于有意义文字**）
  - 圆角 4 / 8 / 12 三档；阴影两档（卡片 `0 1px 2px rgba(16,24,40,.06)`、浮层 `0 4px 16px rgba(16,24,40,.12)`）；间距 4/8/12/16/24/32 刻度
  - 字体栈 `system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`
  - 布局常量：侧边栏 220px（维持现状）、顶栏 56px
- 既有 `chart/palette.ts` **不动**——它是图表分类色板，与 UI 令牌是两个东西（其文件头注释已说明此边界）。
- 对比度测试沿用 `palette.test.ts` 模式：文本类令牌 ≥ 4.5:1、涨跌色 ≥ 4.5:1；`#9CA3AF` 以注释声明豁免并限定用途。

### 外壳与落地页

- `AppShell` 放 shared：浅色侧边栏 + 顶栏 + 内容插槽，导航项/品牌区/用户区由应用注入。它是无业务语义的布局组件，符合 ADR-0003；角色→模块映射等业务配置**留在 internal**。
- 两端共用 `AppShell`。customer 借此次装壳**补上 vue-router**（智能客服/风险测评/产品筛选/我的资产各有真实 URL）——现在 `ref` 切视图的写法让刷新丢状态、URL 不可分享。
- internal 用 `AppShell` 重写 `WorkbenchShell`，保留角色驱动导航与面包屑；**登出入口仍在外壳层**，任何路由任何角色可见（沿袭 internal-workbench-shell 的教训）。
- internal 新增静态模块导航落地页：路由 `/`，渲染登录者可见模块的入口卡片（图标 + 名称 + 描述，数据来自既有 `MODULES` 配置），不聚合任何业务数据。登录后默认落到此页。
- 图标：`@element-plus/icons-vue` 加入两个应用的依赖——本 slice **唯一的新增依赖**，版本跟随 Element Plus。
- 品牌区文案维持现状：customer「智能财富管家」、internal「内部工作台」。

### 复合组件（恰好三个新封装，不再多）

- `StatCard`（shared）：KPI 卡——标题、数值、环比趋势（方向 + 文案）、图标插槽；彩色左边条 3px，accent 只能取枚举 `{primary, up, down, success, warning, danger}`，禁裸色值。
- `SectionCard`（shared）：白卡容器——标题栏 + 操作区插槽 + 内容插槽，页面主体统一经它承载。
- 既有 `ChartFrame` 令牌化：硬编码色值全部换成令牌，行为不变。
- 每加一个共享组件都是一次跨应用耦合承诺；页面级独有模式留在各自应用，不进 shared。

### 逐页改造纪律

- 每个 SFC：内容包进 `SectionCard`，scoped style 里的硬编码色值/间距/圆角替换为令牌，删去被令牌覆盖的冗余样式。
- **令牌纪律**：改造后 SFC 中不得出现裸色值与裸间距（1px 细线等极少数例外需在代码注释说明）。本条靠 review 执行、写进验收基线，**不引入 stylelint**——仓库当前没有 CSS lint 工具链，为一条规则加一套工具是本末倒置；违例反复出现时再补。
- EP 组件内部着色（tag 浅底等）维持库默认，本次不做无障碍加固；自有文本着色一律走令牌。

## Testing Decisions

不新增测试 seam，沿用既有 vitest 组件挂载与纯函数测试。

- 令牌对比度测试（shared，沿用 `palette.test.ts` 模式，涨跌色入测）
- `AppShell`：导航项渲染、登出入口恒在、插槽内容渲染
- `StatCard` / `SectionCard`：props 与插槽渲染、accent 枚举约束
- customer 路由化后：各视图有独立 URL、登录/登出流转不变（补路由层断言）
- 两端既有 vitest 套件与 `pnpm typecheck` 必须全绿——这是「样式重构没碰行为」的底线证据
- 无视觉回归工具（仓库现状），以两端手工走查清单替代

## Out of Scope

- 暗色模式；移动端/响应式适配
- 参考图上有而本系统没有的一切功能：上传持仓截图、添加理财产品、理财顾问列表、真实数据聚合的 KPI 仪表盘
- 后端任何改动
- EP 组件内部着色的无障碍加固
- 各页面信息架构与交互流程的调整（本次只换皮，不动页面结构）

## Further Notes

- 本 spec **取代** `internal-workbench-shell` spec 中的两条决定：「Element Plus 默认主题，不做视觉定制」与「深色左侧导航」。那两条在当时是为了快速落地外壳，现在由令牌层与浅色骨架接任。它们不是 ADR，故无需新增 ADR 推翻——此处显式记录以免后来的读者困惑。
- 未新增 ADR 的判定：令牌进 shared 已被 ADR-0003 预先批准；红涨绿跌是行业通行约定且改两个色值即可逆转；复合组件的划分可随演化调整。三条均不满足 ADR 门槛（hard to reverse / surprising / real trade-off），决定记录于本文件即可。
- `CONTEXT.md` 零改动：本 slice 未产生任何领域术语，全部是呈现层与工程层决定。
- 参考图内容与词汇表的两处出入已在访谈中确认无须处理：图上的「客户管理」对应本系统模块「客户关系」（维持现有命名）；「金牌/资深/高级顾问」分级在数据模型中不存在，属模板占位内容，不引入。
