# 内部工作台外壳与知识库管理

Status: ready-for-agent

前置：`foundation-and-customer-service-slice`（员工身份域的凭证签发、知识库接口层）

## Problem Statement

内部员工现在没有任何可用的界面——内部工作台在上一个 slice 里只做到「能验证客户凭证被拒绝」的程度，登录进去之后是一片空白。

知识库也一样：文档能通过接口入库，但维护者得开 Swagger 手工拼请求体才能上传一份产品手册，想看看库里现在有什么、某个问题的检索命中了哪些片段，都没有地方看。而检索质量是整个系统回答可信度的地基——看不见它，就只能靠一次次去对话框里试。

## Solution

内部工作台有一个完整的应用外壳：登录后看到左侧导航，导航按登录者的角色渲染该角色可见的模块，每个模块有独立 URL，浏览器前进后退正常工作。尚未实现的模块显示占位说明而不是空白页——员工知道系统在设计上考虑过他这个角色。

知识库管理作为第一个真实模块落在这个外壳里：上传文档并选择知识类型、查看已入库文档及其状态、删除文档、以及一个检索试验入口——输入一个问题，直接看到命中的片段、相似度分数与来源，不必绕道对话。

## User Stories

### 通用（所有内部员工）

1. As an 内部员工, I want to 用我的员工账号登录内部工作台, so that 我能进入属于我角色的工作界面
2. As an 内部员工, I want to 我的客户账号在内部工作台登不进去, so that 身份域的隔离是真的
3. As an 内部员工, I want to 登录后看到左侧导航, so that 我知道这个系统还有哪些模块，而不是只有眼前一个页面
4. As an 内部员工, I want to 无论我是什么角色都能正常登出, so that 我不必靠清浏览器数据才能退出
5. As an 内部员工, I want to 每个页面有独立 URL, so that 我能把一个页面的链接存下来或发给同事
6. As an 内部员工, I want to 浏览器后退键能回到上一个页面, so that 我不必去页面上找返回按钮
7. As an 内部员工, I want to 看到当前所在位置的面包屑, so that 在多层页面里我不会迷失
8. As an 内部员工, I want to 看到我自己的姓名与角色, so that 我确认自己是以什么身份在操作
9. As an 内部员工, I want to 凭证过期时被引导回登录页而不是看到一堆报错, so that 我知道该做什么
10. As an 内部员工, I want to 访问我这个角色无权访问的模块时被明确拒绝, so that 权限边界是清楚的而不是靠导航藏起来

### 按角色

11. As a 理财顾问, I want to 导航里显示投顾相关模块的位置, so that 我知道我的工作入口在哪
12. As a 风控专员, I want to 导航里显示风控相关模块的位置, so that 我知道系统在设计上考虑过我这个角色
13. As a 客户经理, I want to 登录后看到完整的应用外壳而不是一句「该模块仅理财顾问可用」, so that 我不会以为系统坏了
14. As an 内部员工, I want to 尚未实现的模块显示占位说明与预期能力, so that 我理解这是还没做而不是出了故障

### 知识库维护者

15. As a 知识库维护者, I want to 在界面上传 txt / md / docx 文档, so that 我不必开 Swagger 拼请求体
16. As a 知识库维护者, I want to 上传时选择知识类型（FAQ / 产品 / 政策）, so that 检索能落在正确的范围
17. As a 知识库维护者, I want to 上传时看到解析与入库进度, so that 我知道一份大文档是在处理还是卡住了
18. As a 知识库维护者, I want to 上传失败时看到失败原因（格式不支持、解析失败、Embedding 调用失败）, so that 我知道该改什么
19. As a 知识库维护者, I want to 查看已入库文档列表及其类型、版本、状态、入库时间、分块数, so that 我掌握知识库的现状
20. As a 知识库维护者, I want to 按知识类型与状态筛选文档列表, so that 文档多了以后我还能找到目标
21. As a 知识库维护者, I want to 删除一份文档并看到确认提示, so that 我不会误删
22. As a 知识库维护者, I want to 删除后该文档不再出现在任何检索结果里, so that 不会出现「文档删了但 Agent 还在引用」
23. As a 知识库维护者, I want to 输入一个问题直接看到检索命中的片段、分数与来源, so that 我能判断检索质量而不必绕道对话
24. As a 知识库维护者, I want to 在检索试验里看到本次最高分是否跨过了兜底阈值, so that 我理解为什么某个问题 Agent 答不上来
25. As a 知识库维护者, I want to 看到即将过期的文档, so that 我能及时更新政策类资料

### 开发者

26. As a 开发者, I want to 侧边栏的可见模块由角色配置驱动, so that 后续加一个模块是往配置里加一项而不是改导航组件
27. As a 开发者, I want to 路由守卫与后端权限校验是两道独立的关卡, so that 前端被绕过时后端仍然拦得住

## Implementation Decisions

遵循 `docs/adr/`。本 slice 直接受 ADR-0003（shared 边界）、ADR-0004（身份域）、ADR-0009（护栏测试）约束。

### 应用外壳

使用 Vue Router 做真实路由，**不用条件渲染切换界面**。这一条明确记录，因为隔壁项目在这里踩过：内部端最初靠组件内状态切换登录、队列、审核三个界面，结果 URL 不变、浏览器后退键无效、页面链接无法分享。

外壳结构：深色左侧导航 + 顶部面包屑 + 内容区。导航项由角色配置生成，配置是一份「角色 → 可见模块」的声明式映射，加模块即加配置项。

**登出入口在外壳层，不在任何页面分支内**——任何角色、任何路由下都必须可见可用。这同样来自隔壁的教训：某个角色落到「无权限」分支时连登出按钮都没渲染，只能手工清浏览器存储才能退出。

### 占位模块

尚未实现的模块渲染统一的占位页，说明该模块的预期能力与所属 slice。占位页仍在路由内、仍有面包屑、仍能登出——它是一个正常页面，不是错误状态。

### 权限的两道关

前端路由守卫决定**导航是否显示、路由是否可进入**；后端接口独立做角色校验。前端守卫是体验，后端校验是安全边界——绕过前端不应该拿到任何数据。

### 知识库管理

上传是异步的：接口接收文件后立即返回一个处理中的状态，前端轮询或订阅进度。解析、分块、Embedding、入库四个阶段各自可失败，失败原因要能传到界面。

文档列表展示知识元数据表的字段：知识类型、标题、来源文件、版本、状态、入库时间、分块数、过期时间。过期时间临近的文档在列表中有视觉标记。

删除触发三处联动（元数据标记过期、向量删除、原始文件归档），界面上是一次操作、一个确认。

检索试验页直接调用知识检索接口，展示命中片段全文、相似度分数、来源定位，并**显式标出兜底阈值的位置**——让维护者看见某次检索是「勉强过线」还是「远低于线」。

### 前端

Element Plus 默认主题，不做视觉定制。受合规约束的组件只吃样式不吃语义（ADR-0009）。

内部端与客户端共享 `packages/shared` 中的 HTTP 客户端与格式化逻辑；角色配置、导航结构、知识库相关的一切**不进 shared**——它们是内部业务语义（ADR-0003）。

## Testing Decisions

沿用既定的两个 seam，不新增。

### Seam 1 — 后端 HTTP 层

- 员工凭证能登录内部接口，客户凭证不能（护栏测试 2 的延续）
- 角色 A 的凭证访问仅角色 B 可见的接口被拒绝
- 文档上传后出现在列表中，且可被检索命中
- 删除后从列表消失，且不再出现在任何检索结果中
- 上传不支持的格式返回明确的业务错误码而非 500

### Seam 2 — Vue 组件挂载

- 不同角色挂载外壳时，导航渲染出的模块集合不同
- **任何角色、任何路由下登出入口都存在**（这条针对隔壁踩过的坑）
- 未实现模块渲染占位说明，且占位页仍有导航与登出
- 凭证失效时被导向登录页
- 检索试验结果中，低于阈值的命中有明确的视觉区分

路由行为（URL 变化、后退键）在组件层用路由测试工具断言，不引入浏览器。

## Out of Scope

- 客户画像、风险评测、适当性匹配
- 产品筛选与产品库页面
- 投顾内容的生成与审核
- 数据查询、图谱、预警、工单的任何实现（这些模块在本 slice 中只是占位页）
- 知识库的版本管理与回滚
- 文档在线预览与编辑
- 批量上传与目录导入
- 前端视觉重构

## Further Notes

本 slice 的价值有一半在于它是后续所有内部模块的容器——后面四个 slice 的页面都往这个外壳里填。因此外壳的角色配置机制值得做扎实：如果加一个模块需要改导航组件，那后面会改五次。

隔壁项目在这个 slice 对应的位置留下了两条教训，都已写进 Implementation Decisions：路由不能用条件渲染替代，登出不能放在页面分支里。
