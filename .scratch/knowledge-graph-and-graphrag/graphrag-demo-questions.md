# GraphRAG 演示对比问题

「GraphRAG 比纯向量检索更准」不写成自动化断言（依赖具体语料，会是个脆弱且无意义的用例，见 03 号 ticket）。这里备一组问题，答辩时现场对比：关掉图谱路径（把 `graphrag_graph_weight` 调到 0，或指向一个空命名空间）前后，同一个问题智能客服给出的回答与引用有什么差别。

每条问题后标注了会命中哪些图谱工具，方便对答时解释「这段回答是从哪条关系链路来的」。

## 1. 行业集中度

**问「张衡的持仓集中在哪些行业？」**

- 纯向量：知识库里没有任何一段文本回答过这个问题，大概率触发兜底话术，引导转人工。
- GraphRAG：识别出客户实体「张衡」，调用 `customer_industry_exposure` 走两跳（客户 → 持仓 → 产品 → 行业），拿到按市值降序的行业分布，模型据此给出具体占比。

## 2. 客户间共同持仓

**问「张衡和赵启明有没有共同持仓？」**

- 纯向量：同样答不上来，这类关系型问题不存在于任何一段知识库文本里。
- GraphRAG：识别出两个客户实体，触发 `common_holdings`，直接返回两人重叠持有的产品（若种子数据当时没有重叠，可先在测试库插入一条重叠持仓再演示，见 `test_knowledge_graph_tools.py::test_multihop_common_holdings_between_customers` 的做法）。

## 3. 基金经理层面的隐性集中

**问「基金经理邵行还管着哪些产品？」**

- 纯向量：答不上来，或者只能从产品说明书里找到零散的基金经理署名，答得不完整。
- GraphRAG：`fund_manager_products` 一次性列出该基金经理名下全部产品，便于顾问判断客户是否在同一个人身上押注过重。

## 4. 产品的行业构成（单跳，衬托多跳场景）

**问「天璇混合基金主要投在哪些行业？」**

- 纯向量：如果知识库里恰好有这只产品的说明书，能答对；但换一只没有上传说明书的产品就答不上来。
- GraphRAG：只要产品在图谱里存在（图谱覆盖全部在售产品，知识库文档覆盖不一定齐），`product_industries` 总能给出准确的行业构成，不依赖是否恰好上传过说明书。

## 5. 图谱不可用时的静默降级（验证「增强不是依赖」）

**问「天璇混合基金主要投在哪些行业？」，但把 `neo4j_graph_namespace` 指向一个从未同步过的空命名空间**

- 预期：接口仍然 200 返回，回答退化成兜底话术或纯向量结果，`ConversationArchive.tool_calls` 里能看到 `graphrag_fusion` 记录 `degraded: true`、`degradation_reason: "entity_not_matched"`（因为空命名空间下任何实体都对应不到真实节点）。
- 这条不是「更准」的对比，是「优雅降级」的对比——答辩时用来说明图谱挂掉不会拖垮整条对话链路。
