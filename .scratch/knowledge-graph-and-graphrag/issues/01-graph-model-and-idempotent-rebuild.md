# 01 — 图谱模型与幂等全量重建

**What to build:** 一条命令把 MySQL 里的客户、产品、持仓、风评数据投影成 Neo4j 图谱，加上构造的行业与基金经理数据。重建是幂等的全量操作，跑两次结果一样；重建期间旧图谱保持可用。管理员看得到节点与关系统计、上次同步时间与耗时。

图谱是 MySQL 的投影读模型（ADR-0002）。最容易偏离的地方是把它当第二个数据库用——「这个数据在图里查更方便就直接写到图里」，一旦发生，双写一致性问题就回来了，而且会以最难排查的形式出现：两边的数据都像是对的，只是不一样。

**Blocked by:** advisory-agent-and-review-flow #05 — 目标实际对比图与集中度提示

**Status:** ready-for-agent

- [ ] 五类节点：客户、产品、风险等级、行业、基金经理
- [ ] 五类关系：客户持有产品、客户具有风险等级、产品属于行业、产品由基金经理管理、产品适合某风险等级
- [ ] **同步是单向的**：MySQL 是唯一写入源，任何业务写入都不经过 Neo4j
- [ ] **重建是幂等的全量操作**，跑两次结果一致
- [ ] 重建期间旧图谱保持可用，新图构建完成后切换
- [ ] 重建失败时旧图谱仍可用
- [ ] 节点上只放查询与展示需要的属性，不复制 MySQL 整行
- [ ] 构造的行业与基金经理数据与产品数据在业务上自洽
- [ ] 规模满足验收要求（节点数与关系数足以支撑多跳演示）
