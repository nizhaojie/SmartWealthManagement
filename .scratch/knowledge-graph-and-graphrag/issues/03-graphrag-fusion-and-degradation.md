# 03 — GraphRAG 融合排序与降级

**What to build:** 提问时系统识别其中的实体，用它们去图谱走多跳拿到关联实体与关系路径，再把图谱结果与向量结果融合排序后一起注入模型——模型于是同时拿到文本语义与结构关系。图谱不可用或实体识别没命中时，静默降级为纯向量检索，用户照常拿到回答。

**Blocked by:** 02 — 图谱查询工具与多跳场景

**Status:** ready-for-agent

- [ ] 从问题中提取产品名、风险等级、行业、客户姓名、基金经理姓名
- [ ] 识别出的实体要能对应到图中真实节点；对应不上的丢弃，不用它去查询
- [ ] 向量结果与图谱结果按加权综合分排序，**权重可配置**
- [ ] **融合发生在注入之前**，模型拿到的是一组已排序的上下文，不是让它自己权衡两组结果
- [ ] 去重后按综合分降序注入
- [ ] 四类情形静默降级为纯向量检索：图谱查询超时、Neo4j 不可用、实体识别未命中、图谱重建中且旧图不可用
- [ ] **降级是静默的**——回答照常给出，不向用户报错
- [ ] 降级在留痕中记录，便于事后分析图谱实际命中率
- [ ] 融合权重改变时结果排序随之改变
- [ ] 「GraphRAG 比纯向量更准」不写成断言（依赖具体语料，会成为脆弱用例），改为准备一组对比问题用于演示
