# 05 — 降级路径全覆盖

**What to build:** 任何一个外部依赖抖动时，系统给出降级后的服务而不是把错误抛给用户：模型调用失败就退避重试、切备用、最后返回预设兜底；向量检索超时降为关键词检索；图谱超时跳过增强；缓存不可用直连数据库；事件总线不可用则核心链路照常。每一次降级都留痕，于是事后能知道系统实际上有多少时间在降级状态下工作。

**Blocked by:** 04 — Agent 间事件协作

**Status:** ready-for-agent

- [ ] 模型调用失败：按退避策略重试，仍失败切换备用配置，再失败返回预设兜底回答
- [ ] 向量检索超时：降级为关键词检索，仍返回可用结果
- [ ] 图谱查询超时：跳过增强，只用向量结果（与 knowledge-graph-and-graphrag #03 的降级一致，此处补齐其余入口）
- [ ] 缓存不可用：直连数据库，恢复后自动回填
- [ ] 事件总线不可用：记录日志，核心链路继续
- [ ] **每一处降级都在留痕中记录**，可统计降级发生的频次
- [ ] 降级后的回答在前端正常渲染，不因缺少引用而报错
- [ ] 各依赖的超时阈值可配置
- [ ] 每个请求的追踪标识贯穿全链路，出现在响应与所有相关日志行中
- [ ] 各 Agent 的响应时间有统计
