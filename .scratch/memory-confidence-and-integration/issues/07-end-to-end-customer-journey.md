# 07 — 端到端客户旅程

**What to build:** 一条贯穿全系统的长路径能从头走到尾：开户 → 风险评测 → 咨询 → 产品筛选 → 请顾问出具方案 → 顾问审核放行 → 交易 → 风控触发预警 → 工单处置。它验证的是九份 spec 的接缝真能串起来——每一份单独通过不等于合起来通过。

这是整个项目的收口 ticket。

**Blocked by:** 06 — 回放模式与预置演示场景

**Status:** ready-for-agent

- [ ] 完整旅程作为一个 HTTP 层的长用例通过，**不引入浏览器**
- [ ] 用两位测试客户（高净值与普通投资者）各走一遍
- [ ] 旅程中的适当性约束全程生效，无任何环节出现越级产品
- [ ] 送达客户的方案是顾问定稿，不是 AI 原稿
- [ ] 风控预警触发后，投顾侧能看到该客户的风险标记
- [ ] 边界情形各自可通：无画像客户咨询、超长对话、非法输入、并发请求
- [ ] 统一入口能按 Agent 类型正确路由到四个 Agent
- [ ] 全链路的追踪标识可把一次用户可见的结果对应到日志
