# 07 — 客户的最终决定权

**What to build:** 建议送达客户之后，决定权在客户手里。客户可以接受或拒绝；接受是一次**原子操作**——当场跑一遍与直接交易相同的受理校验，通过则成交并产生交易事件，不通过则接受失败、建议留在待客户决定。

**Blocked by:** 06 — 业务操作 Agent 与操作建议原稿

**Status:** ready-for-agent

- [ ] 状态集 `待客户决定 → 已接受 / 已拒绝 / 已过期`；三个终态都是事实陈述，不是流程节点
- [ ] 有效期 **7 个自然日**，过期即终态；过期的建议不能再接受，客户经理可重新发起一条
- [ ] **放行与驳回只开放给理财顾问**；客户经理看得见、评论得了，放不了行
- [ ] 客户侧只读接口：本人待决定的建议与已决定的建议；**未放行的建议任何客户侧接口都读不到**（护栏 5 的第二个出口）
- [ ] 送达视图沿用**服务端裁剪**的做法，不靠前端展示习惯
- [ ] **接受即成交**：复用 02/03 的受理服务与校验，走的仍是 `submit_transaction_event` 这一条路径
- [ ] 接受失败（余额不足、越级、已过期）时**建议留在待客户决定**，客户补足条件后可以再来一次——不留「已接受但成交失败」这个状态
- [ ] 客户决定落成一条记录：谁、什么时候、对哪条建议、接受还是拒绝
- [ ] 断言：未放行的建议在客户侧读不到；客户经理调用放行接口被拒绝
- [ ] 断言：过期后接受被拒绝且状态为已过期
- [ ] 断言：接受时余额不足 → 接受失败，建议仍是待客户决定，且**没有**产生任何交易
- [ ] 断言：接受成功后产生交易且它经过了规则引擎
