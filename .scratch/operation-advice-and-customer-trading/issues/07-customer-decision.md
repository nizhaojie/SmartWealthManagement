# 07 — 客户的最终决定权

**What to build:** 建议送达客户之后，决定权在客户手里。客户可以接受或拒绝；接受是一次**原子操作**——当场跑一遍与直接交易相同的受理校验，通过则成交并产生交易事件，不通过则接受失败、建议留在待客户决定。

**Blocked by:** 06 — 业务操作 Agent 与操作建议原稿

**Status:** implemented

- [x] 有效期 **7 个自然日**，过期即终态；过期的建议不能再接受，客户经理可重新发起一条
- [x] **放行与驳回只开放给理财顾问**；客户经理看得见、评论得了，放不了行

### 几处写下来的决定

**状态不落库，只有「客户真正做的那个决定」落库。** `待客户决定` 是还没有那条决定记录，
`已过期` 是送达满 7 个自然日——两者都是时间的函数，现算即可。落一个「已过期」字段就要
有人去改它，而改它没有任何触发点（没有定时任务、也没有谁会在读的时候顺手写库），
结果就是字段永远是 `待客户决定`。三个终态里只有接受与拒绝是一次人的动作，它们各自留
一条记录；过期不是。

**送达时间取放行那一刻的审核留痕，不新增一列。** 操作建议放行不产生第二份载荷（#06），
所以没有一张定稿表可以拿 `released_at`；放行是一次理财顾问的决定，
`biz_advisory_review_audit` 里那条 `放行` 留痕带着谁、什么时候。从它读比在审核记录上
再加一列更好：那一列会被方案的定稿（`AdvisoryFinal.released_at`）重复一份，而两份口径
迟早对不上。读取侧若查不到放行留痕，宁可回 500 也不要把一条读不出有效期的建议当成
「还有效」——那是 `record_decision` 一次提交里同时写下的两样东西，缺失就是数据坏了。

**送达视图逐项拣选，不 `{**row}` 展开。** `CUSTOMER_VISIBLE_ADVICE_FIELDS` 列出客户能看到
的十二个字段（建议本身的四件事 + 状态、时限、决定结果、免责声明），发起人、内容分类、
客户标识都不在其中。以后往建议里加字段时默认是内部字段——要让它送达客户必须在这里显式
加一次（ADR-0016）。测试断言的是**字段集合相等**而不是「包含」，所以这条边界破了会当场红。

**赎回建议的接受是「按接受时刻的持仓份额全部赎回」。** 建议的金额是 `份额 × 净值`
（#06 的成交口径），方向就是全部赎回；接受时不能拿金额反除净值去还原份额——净值只有
当前值、没有时间序列，金额又按两位小数量化过，反除回来可能比原份额多出一点点，那会被
受理侧的份额校验当场拒绝，成了一条注定失败的接受。按当前持仓份额赎回则把「持仓变少了
就接受失败」这件事交给受理侧，与直接赎回同一套判断。

**客户决定先落库、再由受理的提交把它一起提交。** 接受时先在会话里 `add` + `flush` 那条
决定，再调用 `app.order_acceptance`；受理的 `submit_transaction_event` 会在成交那一刻
提交整个会话，于是「接受」与「成交」在同一次提交里同时成立或同时不成立。校验失败时受理
侧先抛错、这里再显式 `rollback`，那条 flush 过的决定随之消失——这就是「不留已接受但成交
失败」。唯一性由 `biz_operation_advice_decision.advice_id` 的唯一约束兜底，重复接受落成
409 而不是 500。

**客户决定只读本人、放行只给顾问，两道门分开写。** 角色在路由依赖里声明
（`require_employee_role(理财顾问)`），归属与本人判定在查询条件里（`_delivered_advice`
同时按 `customer_id` 与「已放行」过滤）。别人的建议与不存在的建议同义（404）——不确认
他人资源是否存在。

### 与 #08 / #09 的交接

客户侧接口已就位：`GET /api/customer/operation-advice` 返回本人在四种状态下的全部已放行
建议（按送达时间倒序），每条带 `status` / `expires_at` / `decision` / `decided_at`，
「待客户决定」的角标由 `status` 数出来；`POST .../{id}/decision` 的失败语义是受理侧
原文透传（余额不足带「还差多少」、未测评是「请先完成风险测评」、越级是风险等级，
已过期是 409 的过期文案），#08 的失败渲染直接取 `message`。顾问侧的放行 / 驳回 HTTP 入口
在本份落地，#09 的审核页与客户经理视角直接接它们；审核队列里操作建议的载荷摘要
（产品、方向、金额）在 #05 已经就位。
