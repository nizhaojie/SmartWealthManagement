# 03 — 赎回按草案里的份额成交

**What to build:** 赎回建议从一个「全部」变成一个具体份额数，客户接受时按它执行。受理侧早就支持部分赎回（`backend/app/order_acceptance/service.py:250-267` 按份额比例同时减持成本与市值），客户侧自助赎回本来就是按份额的（`backend/app/api/customer_transactions.py:36-38`）——缺的只是建议这一侧把份额存下来并照着执行。

本份顺带修掉一处隐性不一致：改动之前草案只存 `amount`、不存份额（`db/models.py:892`），而接受时执行的是**接受那一刻的全部持仓份额**，于是 `amount` 列只是一个会过期的展示值，且没有任何断言会失败。

**Blocked by:** 02 — 发起受理接手产品与金额 / 份额

**Status:** implemented

- [x] `backend/app/operation_advice/decision.py:331` 从 `_current_holding_shares(db, draft=draft)` 改为读草案的 `redeemed_shares`
- [x] **份额列为空表示「全部赎回」**——只服务改动之前已有的行；新写入的赎回建议一律带份额
- [x] 断言：部分赎回后剩余份额、成本与市值按比例减持，持仓状态仍是「持有中」
- [x] 断言：份额恰等于持仓时成交后持仓状态为「已清仓」
- [x] 断言：赎回建议生成之后客户自己动过持仓导致份额不足 → **接受失败，建议仍在待客户决定**（与余额不足同一套语义，`decision.py:334-337` 的既有回滚路径）
- [x] 断言：改动之前的赎回建议（份额列为空）接受时仍按当下的全部份额成交

**注意：** 「空 = 全部」是既有语义的忠实延续，不是特例。若有人把它读成「可选的全部赎回」而顺手给新行也写空值，`decision.py` 的旧分支会被重新激活，而演示里看不出来——所以新行的空值要有一条断言盯住。

**注意：** 份额持久化之后，赎回的 `amount` 列成了可推导的值（份额 × 净值，净值只有一个当前值），不再有「过期」的问题。它仍然存着，因为它是顾问审核时要看的那个数。
