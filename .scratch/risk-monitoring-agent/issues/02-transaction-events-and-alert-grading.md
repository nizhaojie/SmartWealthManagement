# 02 — 交易事件落库广播与预警分级

**What to build:** 一笔交易提交后先事务性落库，再向事件总线广播，然后过一遍规则引擎；命中即产生带等级与置信度的预警。等级由命中的规则数与该客户的历史情况共同决定。

**Blocked by:** 01 — 规则数据模型与算子求值

**Status:** implemented

- [x] **先事务性落库，再广播**；广播失败记录日志但不回滚——交易记录不能因广播通道问题而丢失
- [x] 广播不可用时预警照常产生
- [x] 分级逻辑是确定性代码，不经过模型：单条命中为轻度，多条交叉为中度，多条命中且该客户有历史预警记录为重度
- [x] 预警记录命中的规则、关联交易、客户、等级与置信度
- [x] **置信度仅用于排序与分级展示**
- [x] **系统不因置信度低而自动关闭任何预警**——这是一个很容易被当作优化提出的想法，它会让预警被系统悄悄消化掉
- [x] 预警产生后向事件总线广播，载荷含预警标识、客户标识、等级、命中规则标识
- [x] 预警是事实记录，不承载处置过程——不要把工单的状态字段塞进预警
