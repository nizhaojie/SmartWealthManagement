# 04 — 规则管理界面

**What to build:** `RiskRulesTab` 从「只读列表 + 启停开关 + 阈值对话框」长成一个规则编辑器：新建与编辑走同一个对话框（判定口径只读）、删除与启停都要收理由、已删除的规则可筛选可见、变更记录有地方可看。

**Blocked by:** `risk-rule-management` #03 — 创建、修改、删除接口与留痕扩展

**Status:** implemented

- [x] 选完字段后算子下拉只剩该字段允许的那几个；阈值输入框的数量与键名随算子的 `threshold_keys` 变化（`gte` 一个、`between` 两个）
- [x] `window_hours` 只在时间窗算子出现；其余算子不出现
- [x] 新建对话框带「创建理由」（必填）
- [x] 新建成功提示必须包含「**新规则从下一笔交易起生效，历史交易不会被重新判定**」
- [x] 「编辑」按钮 → 同一对话框：编号只读，判定形状与阈值四项控件只读，并附一句「要改判定形状请删除后重建，要改阈值请用『调整阈值』」

- [x] 「查看变更记录」→ 只读对话框，渲染 `GET /{id}/changes`（**这个接口此前没有前端入口**）；已删行也要能打开它
- [x] 非风控专员：三个写按钮与开关一律不出现或禁用，沿用既有的只读提示文案

**一处会被忽略的细节：** `include_deleted` 必须是服务端参数。前端拿到当前页再过滤，会让「共 N 条」与实际行数对不上——那正是 `RiskRulesTab.vue:99-101` 那条注释在解释的问题。

**实现时补上的三处（都在 checks 的界线内，只是清单没写）：**

- ① 表单派生逻辑（字段→算子收敛、算子→阈值键、窗长只对时间窗算子、值域提示、待提交阈值的键过滤）搬进 `ruleEditor.ts`：它们全是纯函数，单独测就不必每次挂载一整个 Element Plus 表格去验一遍。
- ② 组件里补一句「含已删除」：`include_deleted` 打开后「共 N 条」里混着已经不算数的行，不说出来就会被读成「现在还算数的规则有几条」；「本页 N 条启用」也把已删行排除在外（它们的 `enabled` 只是一个留在库里的旧值）。
- ③ 窗长与规则权重用数字框（`el-input-number`，窗长 min 1 / 整数，权重 0.50–5.00 两位小数）。「还没填」在本地挡一道（`时间窗必须是正整数小时`）：它会落到 pydantic 的 `int | None` 上换回一句「参数错误」，而这里说得出是哪个控件少了东西。其余各列（名称、规则分类、预警等级、阈值形状、阈值值域）一律不本地判，交给后端当唯一裁判——数字框的区间与后端 `normalize_weight` 的值域是两道，不是一道。

**改到 `packages/shared` 的一处：** `http.delete` 加了可选的 `body`。删除要带一段署名（理由），而理由放进请求体是后端钉下的决定——放进查询串会进访问日志。改动是向后兼容的（`apps/internal/src/knowledge/api.ts` 的调用不用动），并且注释按守卫的要求不含业务词汇（`scripts/business-semantics-guard.mjs` 连注释一起扫）。

**#03 留下的那处不一致已收口：** 启停理由收紧为必填之后，这个开关改成了「点一下先弹理由」——直接点开关会收到 400 的那段时间已经结束。

**启停用 `before-change` 而不是 `change`：** 开关的档位由列表行本身说了算。理由弹框取消、或写接口失败时 `before-change` 返回 `false`，开关当场弹回原档位，不必等一次重取来纠正它；成功时才 `replaceRule(...)` 把行换成服务端返回的那一条。失败路径仍然重取当前页，那是另一件事：写操作被拒可能就是因为这一页旧了（比如这条规则已被别人删掉，而已删除的规则不再接受写操作）。

**一处测试上的坑（会伪装成产品 bug）：** `el-table` 会在隐藏区里为每一列再渲染一份模板（供它算列宽），副本里的 `row` 是个空对象。测试里全局找 `[data-testid="edit-rule"]` 会先命中那个副本，点它等于点了个空行——对话框打开了却字段全空，看起来像「编辑态没把规则读进来」。组件测试一律按 `.el-table__body tr` 的行内查找。
