# Neo4j 是 MySQL 的投影读模型，不是第二个写入源

引入 Neo4j 承载知识图谱与 GraphRAG，但它只读：MySQL 仍是唯一写入源，图谱由 MySQL 单向同步生成，脏了就全量重建，不做双向同步。

## Consequences

代价是图谱有同步延迟。这对本项目的图谱用途（客户画像、行业分布、持仓穿透）可以接受，这些场景本就不要求实时。

收益是避开了双写一致性——如果客户、产品、持仓在 MySQL 和 Neo4j 各存一份可写副本，两边漂移时无法判定谁对。投影模型下这个问题不存在：MySQL 永远对，Neo4j 错了就重建。

需求文档为持仓穿透同时指定了 Neo4j 多跳查询；本项目两条路都留着——穿透用 MySQL 递归 CTE（深度通常只有两三层，CTE 足够且无延迟），图谱用于行业关联与多跳语义检索。
