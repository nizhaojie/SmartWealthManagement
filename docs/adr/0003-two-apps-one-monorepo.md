# 前端是两个独立应用，同处一个 pnpm monorepo，shared 层禁止承载业务语义

客户端与内部工作台是两个独立构建、独立部署的 Vue 应用，放在同一个 pnpm workspace 里共享 `packages/shared`。

## Considered Options

- **单一应用按角色渲染界面**——被拒绝。客户的浏览器会下载到内部功能的代码：风控规则字段名、预警分级逻辑、审核流状态机。即使路由守卫挡住了入口，这些仍躺在同一个 bundle 里，扒开 sourcemap 就能读。
- **三个应用（客户端 / 投顾工作台 / 风控台）**——被拒绝。内部三个角色共用客户查询、产品库、画像面板等大量组件，拆三份会重复。
- **两个完全独立的工程，共享代码靠复制**——被拒绝。统一响应格式拆包、JWT 注入、错误码映射、风险等级映射表这些改一次要同步两遍。

## Consequences

monorepo 会持续诱使人把「两边都要用」的东西塞进 `packages/shared`，而这正好会把上面第一条拒绝理由重新引回来。因此边界是硬的：**shared 只允许放与业务语义无关的东西**——HTTP 客户端、主题令牌、日期与金额格式化、图表壳。风控规则字段、预警分级、审核流状态机、画像研判权重一律不许进。这条边界靠构建期检查保障，不靠自觉。
