# 身份域延伸到表结构：客户与员工分两张表

需求文档用一张 `sys_user` 表加 `user_type` 字段区分客户与员工。本项目改为 `sys_customer` 与 `sys_employee` 两张表，与两个身份域、两套 token 受众、两个前端应用一致。

## Consequences

单表方案的问题是 `employee_role` 与 `customer_level` 两个字段永远有一个是 NULL，且每一处查询都必须带上 `WHERE user_type = ...`。只要有一处漏写，客户就会出现在员工列表里——而这正是评分表中「适当性违规 -10」与「无权限校验 -10」的典型成因。拆表后这类错误在编译期或 SQL 层就不成立。

代价是需求文档的 10 张表变成 11 张，Phase 1 验收标准写的「10 张表全部创建成功」需要在答辩时解释一句。
