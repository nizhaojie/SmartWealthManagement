# 产品筛选与产品推荐是两件事，客户侧只开放筛选

客户提出带条件的选品类问题时（例如「有什么年化 5% 以上的稳健型理财」），智能客服 Agent 返回产品筛选结果——按已披露客观要素过滤，**强制按产品代码排序**，不做任何评分、排名或适配性表述——同时提供「请顾问出具方案」入口，转为一份待审核的投顾内容异步处理。

需求文档把上面那句提问列为客服 Agent 的典型场景，但它本质是在要推荐。这里做出与文档字面意思不同的处理，因此记录。

## Consequences

排序本身会传递推荐语义：列在第一位的看起来就是最优的。所以排序键必须是与优劣无关的产品代码，**不能是收益率**。这与 Element Plus 表格提供可排序表头的默认习惯相反，客户端的产品列表需要显式关掉收益率排序——这条在后期「优化体验」时极易被无意破掉，由护栏测试守住。

当筛选结果少于三条时，结果事实上接近推荐，此时不得隐藏「这不是推荐」的说明。

这样客户并非被拒答，而是拿到自己有权看到的事实，另有一条通往持证人员的显式路径。
