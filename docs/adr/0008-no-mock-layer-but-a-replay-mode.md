# 开发期不建前端 mock 层，改为后端提供确定性回放模式

前端直连真实后端开发，不引入 MSW 一类的 mock 层。另设一个由环境变量 `DEMO_REPLAY` 控制的回放模式：预置若干条问答的完整响应（含引用、SQL、预警），不依赖 LLM 与向量库是否健康。

## Consequences

不建 mock 的前提是前后端由同一个人按竖切顺序开发，接口写完即可接入。若改为多人并行，这个决定要重新审视——那时前端会被后端堵住，mock 层的成本就划算了。

回放模式的用途是答辩现场兜底。演示当场依赖六个容器与外部 LLM API 同时健康，任何一环抖动就是评分表里「项目无法启动 -20」在评委面前发生。它同时充当集成测试的夹具。

这不是造假：需求文档 F5.3 本就要求「LLM 调用失败 → 指数退避重试 → 切换备用模型 → 仍失败则返回预设兜底回答」，回放模式是把那条降级路径做得体面一些。
