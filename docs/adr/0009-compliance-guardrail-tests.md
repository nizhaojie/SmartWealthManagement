# 测试只覆盖合规不变量，不追求覆盖率

不写常规意义上的单元测试套件，只写一组针对合规不变量的护栏断言：

1. 适当性硬过滤——C1 客户的候选池里不出现 R2 以上产品
2. 身份域隔离——客户 token 打到任一内部接口返回 401 或 403
3. NL2SQL 只许 SELECT——DROP / DELETE / UPDATE / INSERT / ALTER / TRUNCATE 一律拒绝
4. 客户端产品列表只按产品代码排序，不提供收益率排序（见 ADR-0005）
5. 投顾内容未经审核不可送达客户
6. `packages/shared` 不含业务语义（见 ADR-0003），构建期检查

## Consequences

这些测试买的不是评分表里「代码质量优秀（有单元测试覆盖）+2」那两分，而是「适当性违规 -10」与「安全事故 -10」两条不发生。它们守的都是「写的时候明明是对的、后来某次改动悄悄破掉」的那类不变量，在一个人连续开发五周、后期赶进度的情况下风险最高。

Element Plus 的默认组件行为会与第 4、5 条产生摩擦：`el-table` 默认带分页器而分页器是真实 `button`，`el-alert` 硬编码 `role="alert"`。因此定下一条规则——**受合规约束的组件只吃样式、不吃语义**：保留自有的 DOM 结构与全部 ARIA 属性，Element Plus 只提供外层容器与主题令牌。不改测试去迁就组件，那等于把护栏拆了。
