# 客户历史记录复用会话归档，只读脱敏呈现，不新建表

需求要求客户侧智能客服支持查看历史记录。归档 `conversation_archive` 已经存在（ADR-0012
确立其为合规留痕：每轮问答即时落库、PII 脱敏、不参与上下文组装），内部端也已能按会话或
客户回溯。客户侧此前没有任何历史查询能力——前端登录/登出即清空，后端也没有客户身份域的
查询端点。

> **修订（2026-09-27，见 ADR-0028）**：客户侧的数据回答开始携带一张结果表，客户历史
> 详情因此**显式**新增 `data` 一项（决定 4），且落库的结构化结果**不过** `mask_pii`
> （决定 5）——那三条正则认的是自然语言文本里的 PII 形态，而结果表的字段面是视图定义的
> 封闭列集合。其余决定（复用归档、客户身份域只读、列表标题、姓名打码的代价）全部不变。
> 下方「决定」按修订后的口径重述。

## 决定

1. **复用 `conversation_archive`，不新建客户历史表。** 数据与脱敏逻辑已在，新建表是重复
   造轮子并引入双份数据不一致风险。

2. **客户侧新增只读查询，走客户身份域。** `GET /api/customer/conversations`（列表）与
   `GET /api/customer/conversations/{session_id}`（详情），可见范围天然收紧到本人：
   列表把 `user_id` 定死为当前客户、并排除当前会话（当前会话在对话页可见，历史只收
   「已结束的登录会话」）；详情按 `session_id + user_id` 过滤，别人的会话与不存在同样
   返回 404，不暴露存在性。

3. **历史是只读回看，不进入上下文。** 与 ADR-0012 一致：归档回答「当时发生了什么」，
   不回答「系统现在记得什么」。查看历史不改变当前会话的上下文。

4. **详情只给 role / content / citations / 时间，以及 `data`。** 前三项之外的另一项
   是数据回答那一轮的结果表（ADR-0028）：要送达客户得**显式**加一次（与 ADR-0016 同一条
   纪律），无表时为 `null`。`tool_calls` 与 `content_classification` 是内部/合规字段，
   不进客户可见视图，内部端的会话详情也不加 `data`。

5. **内容沿用归档的脱敏版。** 客户看到的自己姓名也以码呈现（如「张先生」→「张*」），
   不为客户另存原文。这条只适用于自然语言文本：结构化结果（`data`）不过脱敏，它的
   字段面与取值都来自客户可见视图的封闭列集合。

6. **列表标题 = 该会话第一条用户提问。** 需要额外查询每条会话的首条 user 消息，批量取
   （一次 in 查询），不逐会话查，避免浏览 100 条历史退化成 100 次查询。

## Consequences

**客户看到自己的姓名被脱敏，这是为省去双份存储接受的代价。** 客户知道自己叫什么，
脱敏不造成信息损失；为此引入「客户可看原文」的第二份存储会同时扩大「客户可见视图」的
边界与一致性负担，不划算。

**历史列表与内部端会话查询复用同一张表、但走不同的可见范围。** 内部端按客户经理归属
收紧（`customer_scope`），客户侧按本人收紧；两者都只读、都不进上下文，但字段与权限
口径不同，因此不共用同一个查询函数。

**本能力天然落在身份域隔离护栏下（ADR-0009 护栏 2）。** 客户凭证在内部端点上无效，
内部凭证在客户端点上无效；客户历史查询额外把可见范围钉死在本人，越权读被挡在 404。
