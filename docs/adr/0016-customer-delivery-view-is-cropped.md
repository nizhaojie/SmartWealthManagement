# 投顾内容送达客户时只暴露客户可见视图内的字段

顾问定稿同时供两端读取：内部端拿它做审核举证与回看，客户侧拿它作为送达内容。这两件事要的东西不一样——定稿里的 `warnings` 是写给理财顾问的话（「请核实后再采用」「生成方案前请先确认处置情况」）并含风控预警摘要，推荐理由引用了画像标签，排序依据是让顾问判断排序是否合理的材料；而**客户可见视图**把这几类都排除在外。因此客户侧不共用内部端的序列化，另有一个只输出客户可见视图内字段的 `serialize_final_for_customer`，客户拿到的那个子集叫**客户送达视图**。

## Considered Options

- **前端裁剪**（接口返回全量，页面选择不显示）：被否。客户可见视图的边界会因此退化成前端的展示习惯，下一个出口——导出、分享、对外集成——会各自漂移。
- **复用内部端的 `serialize_final`**：被否。内部端要 `warnings` 与排序依据，客户侧不能要，同一个函数服务不了两端；合一的结果只会是内部字段继续流出。

## Consequences

定稿在客户侧不是一个完整对象，而是它的一个子集。以后往定稿里加字段时，默认是内部字段——要让它送达客户，得先在 `serialize_final_for_customer` 里显式加上，并且问一次它是否落在**客户可见视图**以内。
