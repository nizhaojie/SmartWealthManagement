# 业务操作 Agent 与投顾助手是两个 Agent，分工在产物

客户经理要为名下客户发起单笔申购/赎回建议，而这条建议必须经理财顾问放行才能送达客户。我们没有让投顾助手兼任这个职责，而是新增第五份 Agent 配置（业务操作 Agent），两者按**产物**分工：投顾助手出配置方案，业务操作 Agent 出单笔操作建议。技术上是同一套运行时（ADR-0007 不变），合规上是同一条审核流水线。

理由是不兼任：投顾助手的输入是画像与持仓、产物是配置方案、操作者是理财顾问；业务操作 Agent 的输入是候选池与资金账户、产物是单笔操作建议、操作者是客户经理。把两者塞进一份配置，提示词与工具集会被两套目标拉扯，而「谁在什么场景下用哪个 Agent」也会失去具体的判据。

## Consequences

- `CONTEXT.md` 的「Agent 配置」由「四个 Agent 四份配置」改为五份；四个变五个本身不推翻 ADR-0007。
- 两个 Agent 的产物都是投顾内容，都走同一条审核流水线（ADR-0020），区别只在内容类型。
- 「给客户推产品」这类需求以后要先问清是哪个：面向配置的给投顾助手，面向单笔执行的给业务操作 Agent。
