# 转账不进交易流水表，客户侧的流水是一张合并视图

交易流水表的产品外键是非空的，而转账没有产品。我们把转账放进独立的一张表，而不是把产品外键改成可空后让转账行留空；客户侧的「交易流水」接口合并两张表按时间倒序返回。

理由：改产品外键为可空，等于让「交易流水」这个集合里出现没有产品的行——资产页、语义视图、持仓穿透、以及所有按产品读流水的地方都要开始处理空值，而它们中的大多数拿一笔没有产品的流水没有任何事可做。风控侧不受影响：它的交易事件模型里产品本来就可空（`app/risk_monitoring/context.py` 的 `TransactionEvent`），说明风控从一开始就没有假设交易一定有产品。

客户侧合并读，是因为对客户来说申购、赎回、转账都是「我动过的钱」。分成两个列表会让他在两个地方找同一笔账，而核对资金流出恰恰是他最想看的事。

## Consequences

- 客户侧的交易流水接口从单表查询变成两表合并，排序键与分页要一起处理。这是这套设计唯一一处非平凡的读模型改动。
- 转让记录的序列化没有产品名，界面要给它一个不依赖产品的呈现（收款人信息）。
- 若将来出现「内部账户互转」，它仍然属于这张表，但会引入客户之间的可见性问题——那是一个新决定，不是本条的延伸。
