# 投顾内容的审核只有一条流水线

「投顾内容 / AI 原稿 / 顾问定稿 / 审核」在词汇表里本来就是与内容类型无关的抽象——四个定义里没有一处提到「方案」，只有表是方案专用的。所以操作建议进来时，我们**就地泛化既有的审核记录表**（加内容类型与内容引用），让两类内容共用同一条审核队列、同一套中断与恢复机制，内容载荷各自建表；而不是给操作建议另建一套平行的 draft / review / final。

理由：护栏「未经审核的投顾内容不可送达客户」必须只有一个出口。平行的第二套流水线意味着这条护栏要守两个出口，而两次实现之间迟早漂移——漂移一次就是一次合规缺口，且不会有任何测试报错。

## Consequences

- 审核记录表名仍带方案的字样，却装着两类内容。这是刻意留下的不一致；改动它要连同数据迁移与两个前端一起动，收益只是命名好看。
- 内容载荷分表，所以方案特有的字段（候选池快照等）不会以一堆空列的形式跟着操作建议走。
- 以后再加第三类投顾内容（例如财富报告），默认走这条流水线；另起一套需要先推翻本 ADR。
