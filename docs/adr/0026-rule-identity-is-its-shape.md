# 规则的身份就是它的判定形状

风控规则现在可以由风控专员创建、修改与删除，于是必须回答「改了什么就不再是同一条规则」。决定：**判定形状（字段、运算符、时间窗）不可修改**，对所有规则一视同仁，包括种子播下的 20 条；要换判定方式只能删除后重建。可修改的只有名称、规则分类、描述、预警等级与权重，而阈值与启停各有专门入口、各自单独留痕。

这条线画在这里，是因为规则编号是一个跨表的外部标识。`fin_risk_alert.rule_codes` 是命中那一刻的 JSON 快照，会永远留着；`fin_risk_rule_change` 按 `rule_id` 记着谁在什么时候把它改成了什么。改判定形状不会让这两处报错——它们只会从此解释一个不存在的口径。这正是最难发现的一类失真：没有断言会失败，只有一个风控专员在半年后对着一条历史预警，用今天的判定形状去理解它。

顺带把「可写」的边界钉在同一处：专员能配的是**组合**（在给定的字段、算子与值域里挑），不是**表达**（拼逻辑、造新算子）。`operators.py` 与 `fields.py` 两处开篇都写着算子与字段集合是有限且封闭的；规则数据一旦能拼逻辑，它就是存在数据库里的代码，既不可测也不可审。因此写入侧的三档校验（名录、字段×算子允许矩阵、阈值值域）不是可选的好习惯，而是这条决定的执行机制——少了它，一个各列都合法但搭配不成立的组合会被收下，直到下一笔交易到达才抛错。

## Considered Options

- **允许改判定形状，并把历史预警一并重写**——被拒绝。预警是事实记录（`CONTEXT.md`），重写等于用今天的口径改写昨天发生过的事；而且它要连带动 `rule_hits`、工单派生与广播。
- **允许改判定形状，但只对新交易生效（历史预警按旧形状解释）**——被拒绝。库里没有「这条预警属于哪个形状版本」这个维度，加它等于给规则做版本化，而这一刀只需要一条能配规则的路径。
- **给判定形状也开一个专用入口并单独留痕**——被拒绝。形状变更的语义是「换了一条规则」，用一条变更记录描述它，读者仍要自己比对前后两份配置才知道发生了什么。

## Consequences

删除后重建得到的是一条新规则、一个新编号。历史预警仍指向旧编号，因此两条规则会在审计视角下并存——这是刻意的，不是遗漏。
