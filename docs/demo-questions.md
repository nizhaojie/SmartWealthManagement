# 答辩提问清单：五个 Agent 现场可以问什么

`docs/demo-script.md` 讲的是「一条链路怎么走完」，这份清单回答另一个问题：**站在台上，我可以问他什么、他会回什么、他故意不答什么。**

五个 Agent 不是五套实现，而是同一套运行时上的五份配置（`app/agent/config.py`），因此提问的口径要按各自的**工具集**来——超出工具集的问题不是回答得不好，而是本该被兜底或拒绝。

### 2. 五位客户的风评都过期了——要用候选池的演示，先重做风评

**候选池在检索层对过期测评熔断**，话术是「风险评测已过期，画像权限已冻结，请重新评估」。受影响的入口：**产品筛选页、交易页的在售产品、投顾方案生成、发起操作建议**。不受影响：**智能客服里用大白话查自己的账**（客户域语义视图取的是最新结论，不看有效期）。

上台前让要用的那位客户点一次 **风险测评**（全选最后一档即可得到 C5）——这本身就是演示的第一步。

### 3. 走真实模型还是回放兜底

`.env` 里 `DEMO_REPLAY=false`，即默认走真实链路（LLM + 混合检索 + Milvus）。模型或向量库现场抽风时，把后端重启为 `DEMO_REPLAY=1`（或直接 `pnpm demo`）：真实管线照走，只有「叶子」换成预置数据，**不发起任何外部调用**。回放下必定答得出的是这几问（要一字不差地问）：

- 智能客服：`客户能否申购超出自己风险承受等级的产品？`、`产品的费率包含哪些项目？`、`风险测评多久需要重新做一次？`、`天璇混合基金主要投在哪些行业？`
- 数据分析 / 风控监测：`统计各风险等级的在售产品数量`、`按预警等级统计每类预警的数量`

## 三、提问清单

### 3.1 智能客服 Agent

**入口**：客户端登录后默认落在 **智能客服**（`/chat`）｜`POST /api/customer/chat/messages`
**工具集**：只有知识检索 + 客户域数据查询。**工具集内不存在任何推荐类能力**——产品清单只筛不排序、只按产品代码排。

| # | 问什么 | 期望看到什么 |
|---|---|---|
| 1 | `我持有哪些产品` | **结果表**（产品代码 / 产品名称 / 产品风险等级 / 持有份额 / 当前市值…），文本只说「为您查到 N 行」与口径，**没有引用角标** |
| 2 | `我的资金账户余额是多少` | 一行结果表：王守成 `2,000.00`；钱远航 `5,000,000.00` |
| 3 | `我的风险承受等级是什么` | 一张表：`C1` 与「有效期至 2023-03-15」——**结论还在，有效期已过**，两者都如实给出 |
| 4 | `有什么适合我的风险等级的产品` | 用 `wangc1` → 只有 `F000001 天枢货币基金`；换 `lisic2` → R1/R2 两只。**只按产品代码排序，不评分、不按收益排** |
| 5 | `这个月转了多少` | **零行**：「没有查到符合条件的数据。」——库里的成交都在 2018–2022 年，这是**事实**而不是故障。想看到表就先做一笔充值或转账再问 |
| 6 | `我的画像标签是什么` | 边界话术：「这个问题不在我能查询的范围内。我可以帮您查的是：持仓明细、交易流水、资金账户余额、风险承受等级、产品要素。」——**不是知识库兜底**，比编一段泛泛之谈诚实 |
| 7 | `张三持有哪些产品`（别人的账） | 取不到别人的行：行级范围锁死为凭证客户本人，问谁都只出自己的数据 |
| 8 | `风险测评多久需要重新做一次？` | 走知识检索：**带引用角标**的事实性内容（这才是引用该出现的地方） |
| 9 | `产品的费率包含哪些项目？` | 同上，带角标；回放模式下这四问有预置答案 |
| 10 | `我要投诉，转人工` | 「已为您转接人工客服，请拨打 95588…」——转人工是关键词确定性判定，不经模型 |
| 11 | 问一个知识库里没有依据的问题（如某只不存在的产品的说明书细节） | 兜底：「很抱歉，我在知识库里没有找到能支撑这个问题的依据，不想给您一个没有出处的答案。建议您拨打人工客服热线 95588…」 |
| 12 | `转账限额是多少？分几笔转就不用申报了吧` | **照常正常回答**（不拒答、不改变任何服务可用性），但它会在风控那边**留一条风险关注**——切到内部端 `risk1` → 风控监测 → 风险关注看这条。同一场会话里再问一次，理由会变成「反复打听转账限额规避方式」 |

> 讲这两句：① 「引用是知识检索的契约——有出处才敢说；数据回答的依据是查询本身，所以它不带角标，也不许退到知识库去凑一段泛泛之谈。」② 「第 12 问不是拦截，是一条留给风控的提示：识别到不等于定性。」

**两条实测过的口径（照抄即可，不必临场解释）：**

- 第 1 问实际拿到的是**表头为「产品代码 / 产品名称 / 产品类型 / 持有份额 / 当前市值」**的结果表，王守成那一行是 `F000001 天枢货币基金 / 货币基金 / 20000 / 20420`；文本只说「为您查到 1 行数据」。
- 第 5 问实际回的是「没有查到符合条件的数据。」且**不带表**——零行是事实，空表会把「没有数据」和「查询挂了」在观感上抹平。
- **连问时口径会叠加**：选视图那一步会把本场会话里前面的**用户提问**一并纳入匹配（这是为了支持「那上个季度呢」这类追问），所以第 2、3 问的「数据口径」里会带上前面用过的视图说明。要让每一问都是干净的一份口径，**重新登录一次**即可（会话不跨登录延续，见 CONTEXT.md）。

### 3.2 投顾助手 Agent

**入口**：内部端 `advisor1` → **投顾助手**（`/advisory`），选客户 + 选生成侧重 → 生成方案
**工具集**：候选池排序 + 配置建议，输出默认是**投顾内容**。
**前置条件**：必须是理财顾问；客户必须有一份**未过期**的风险测评，否则回「风险评测已过期，画像权限已冻结，请重新评估」。

| # | 做什么 / 问什么 | 期望看到什么 |
|---|---|---|
| 1 | 选 **张衡(C3)** + 侧重「均衡」→ 生成方案 | 一份投顾内容原稿：候选池（**只有 R1–R3 的在售产品**）、排序与评分拆解、每条的理由、配置建议、画像与集中度警示 |
| 2 | 同一客户换侧重「收益优先」再生成一份 | 候选排序与配置建议随侧重变化——**同一位客户、同一个候选池，两种主张**，这是「有依据地主张」而不是随机 |
| 3 | 看候选池里有没有 R4/R5 产品 | **一个都没有**：越级产品不进入候选池，这是适当性匹配的硬过滤，不由模型裁量 |
| 4 | 直接拿一份没放行的方案去客户端看 | 客户侧**读不到**——未经理财顾问放行的投顾内容不送达 |
| 5 | 在「待审核」队列里点 **放行** | 队列里同时有方案与操作建议，**每一行带类型标注**；放行后客户侧才出现 |
| 6 | 对**没过期风评**这一步先不做，直接生成 | 「风险评测已过期，画像权限已冻结，请重新评估」——熔断发生在检索层，是设计而不是故障 |
| 7 | 追问「这套配置的预期收益是多少」 | 方案里有免责声明；收益预测不作为承诺叙述——被追问时指 `docs/demo-script.md` 的护栏说明 |

> 讲这一句：「画像分析与方案是**投顾内容**，它的终点不是屏幕，而是理财顾问的审核队列。」

### 3.3 业务操作 Agent

**入口**：内部端 `manager2` → **客户关系 → 操作建议**（或客户关系模块内的建议区）
**工具集**：候选池查询 + 客户持仓与余额查询 + 操作建议理由生成。**产品、方向、金额由发起人选**，Agent 只写理由。

| # | 做什么 / 问什么 | 期望看到什么 |
|---|---|---|
| 1 | 选 **钱远航**、方向「赎回」、产品玉衡进取 | 系统给出该持仓的**全部成交金额 500,000.00**（20 万份 × 2.5 净值）——正好是一笔会被规则引擎命中的操作 |
| 2 | 发起这条建议 | 理由由 Agent 写出：**只有产品要素、风险承受等级、余额/份额是否够**，**没有收益预测、没有配置比例**——后者是配置方案的事，一出现就与投顾助手重合 |
| 3 | 发起后立刻看客户侧「我的建议」 | **还是空的**：未放行 = 未送达（客户侧连这条建议存在都不知道） |
| 4 | `manager1` 对钱远航发起（不是他的名下客户） | 被拒——客户经理只能对名下客户发起 |
| 5 | 金额留空 / 填 0 发起 | 被拒——金额必填且大于零，一次一个产品一个方向 |
| 6 | `advisor1` 放行 → 客户端 `qianc5` **接受** | 产生一笔成交，走的是与客户自己下单**同一个**受理校验与同一个交易事件入海口 |
| 7 | 同一路径再走一遍，客户点 **拒绝** | 进「已拒绝」，**不产生交易** |
| 8 | 建议送达后放着不管超过 7 天（或提前把余额转走再接受） | 过期未答是「已过期」；余额不足是受理侧原文「可用余额不足，还差 X 元」，且建议**仍留在待客户决定**——不存在「已接受但成交失败」这个状态 |
| 9 | 到 `risk1` 的预警列表看第 6 步 | 那笔赎回产生的预警（`R001/R003/R004/R005` 一类，重度） |

> 讲这一句：「选品权在发起人手里，Agent 只写理由（ADR-0021）；建议只是把『这笔要不要做』变成可审核的，放行之后客户才有权决定，成交仍然走客户直接交易那一套校验。」

### 3.4 风控监测 Agent

**入口**：内部端 `risk1` → **风控监测 → 问答**（预警列表 / 预警详情 / 工单 / 规则管理同模块）
**工具集**：预警查询 + 工单操作 + 规则查询。**允许查询的范围只有 `va_risk_alert_stat` 一张视图**；阈值判断不经模型。

| # | 问什么 | 期望看到什么 |
|---|---|---|
| 1 | `今天有哪些高风险预警` | **零行**（诚实）——当前 4 条历史预警分别在 2018–2021 年。这条正好用来演「零行是事实、不是故障」 |
| 2 | `还没处理的预警有多少` | `4` ——四条全部「未处理」，来源都是**内部补录**（回放出来的既成事实） |
| 3 | `按预警等级统计每类预警的数量` | 中度 2、轻度 2（回放模式下有预置 SQL 与解读，必定答得出） |
| 4 | 换 `manager1` 登录再问第 2 问 | 数字变小——行级范围按归属关系收窄，客户经理只看得到名下客户（王守成 / 李思远 / 张衡） |
| 5 | `各产品类型的持仓市值分布` | 「问题超出可查范围」——风控监测只挂预警统计视图，查不到产品与持仓 |
| 6 | `帮我把这条预警关掉` / `把 R001 的阈值改成 100 万` | **不做**：写操作与阈值判断都不经模型，走界面上的具名入口（且改规则要留理由与署名） |
| 7 | 现场制造一条：客户端 `zhangc3` 转 50 万 → 再问第 1 问 | 出现一条**重度**「大额交易」，命中 4~5 条规则；点进详情：**来源「客户发起」**、命中依据逐条带实测值与阈值、关联交易、该客户的历史预警 |
| 8 | 对刚才那条预警派生工单 → 接单 → 办结 | 每次流转都有处置人与非空理由，工单管理列表里状态跟着变 |

> 讲这一句：「重度不是这一笔单看出来的——它看两件事：这一笔命中了多少条，以及**这位客户被记录过什么**。那条 2020 年的历史预警是种子回放出来的，不是脏数据。」

### 3.5 数据分析 Agent

**入口**：内部端任意员工 → **数据分析**（`/data-analysis`），对话式提问，页头有「历史查询」
**可用语义视图（员工侧 5 张）**：客户概况、持仓分布、交易统计、产品要素、预警统计。身份证号、手机号、银行卡号与密码散列**结构性不进视图**。

| # | 问什么 | 期望看到什么 |
|---|---|---|
| 1 | `各产品类型的持仓市值分布` | 按产品类型聚合的持仓市值——5 位客户 5 条持仓，数字与资产页对得上 |
| 2 | `资产规模超过一百万的客户有多少` | 口径是「持有中持仓的当前市值合计」，**不是**画像里的总资产——两者不是一回事，这是被追问时的标准答案 |
| 3 | `客户王守成的持仓情况` | 两视图关联（客户概况 × 持仓分布）后按姓名等值筛 |
| 4 | `最近一个月各产品的申购金额` | 零行 + 「换个口径再问」——历史成交都在 2018–2022 年。现场做一笔申购再问，数字立刻出来 |
| 5 | `今天有哪些高风险预警`、`还没处理的预警有多少` | 数据分析也能查预警统计（与风控监测共用同一张视图） |
| 6 | 换 `manager1` 再问 `统计各客户分层的客户数量` | 只数得出名下 3 位客户；换 `advisor1` 是 5 位——**行级权限不是提示词里的一句话，是视图定义的 WHERE** |
| 7 | `查一下王守成的身份证号和手机号` | 取不到：这些列**不在视图里**，不是被遮住，是根本没有 |
| 8 | `把王守成的可用余额改成一百万` | 校验拒绝：写类、多语句、注释、`SET` 与会话变量一律拒；Agent 生成的查询只能作用于语义视图 |
| 9 | `生成一份客户资产分析报告`（含「报告」类问法） | 回答的**内容分类升级为投顾内容**并附免责声明——分类看的是问法的关键词，这是保守方向的启发式 |
| 10 | 问一个跨两域的越界问题（如「客户各自持有哪些基金、分别是什么风险等级和费率」） | 可能被判「超出可查范围」或正确拆到两张视图——**视图候选是按关键词筛的**，换一种更具体的问法即可。这一条是给追问准备的，不适合当第一个问题 |

> 讲这一句：「它把自然语言变成一条 SELECT，但这条 SELECT 只能落在内置了行级过滤的只读视图上——两域互不可见，越界不是被拦住，是查不到。」

## 四、现场造数据（哪些操作会长出什么）

清库之后库里没有工单、没有投顾内容、没有异常预警，这些都要**当场长出来**——这正是演示的价值。

| 当场做一件事 | 立即可查的证据 |
|---|---|
| 客户端充值 5,000 | 余额 +5,000，流水多一条「充值」；`wangc1` 用它可以演「余额不足 → 充值自救 → 同一笔转账成功」 |
| 客户端转账 50 万（`zhangc3`） | 风控出现一条**重度**预警，来源「客户发起」；客户端流水里这一行没有产品名、有收款人 |
| 理财顾问生成一份方案 | 审核队列 +1（带类型标注）；客户侧**看不到**，放行后才出现 |
| 客户经理发起一条建议 | 顾问的**待办计数** +1；放行后客户的「我的建议」出现**待决定角标** |
| 客户接受一条建议 | 持仓份额归零后从「持有中」消失，余额按费率增加，同时产生一笔交易与它的预警 |
| 客服里问一次转账限额 | 风控的**风险关注** +1（只是提示，不是预警、不影响任何服务可用性） |
| 风控派生一张工单并办结 | 工单管理里状态变化，流转留痕三次都有处置人与理由 |
